# Blog Post Proposals

This directory contains blog post proposals generated by the Blog Post Proposer Agent. Proposals are automatically created when significant PRs are opened or merged.

## Directory Structure

```
proposals/
├── README.md                                    # This file
├── YYYY-MM-DD-pr-<NUMBER>-<slug>.md            # New blog post proposals
├── YYYY-MM-DD-update-<article-slug>.md         # Updates to existing posts
└── YYYY-MM-DD-pr-<NUMBER>-analysis.txt         # Low-priority analysis (score < 5)
```

## Proposal Status

Proposals use status badges to track progress:

- 📝 **Proposal** - Initial proposal, awaiting review
- ✍️ **Drafting** - Approved, currently being written
- 📊 **Review** - Draft complete, in review
- ✅ **Published** - Article published to blog

## Automatic Generation

The Blog Post Proposer Agent runs automatically on:

1. **PR Opened** - Initial analysis and proposal generation
2. **PR Merged** - Final metrics update and "ready to draft" status
3. **Manual Trigger** - Via GitHub Actions workflow dispatch

### Workflow

```
PR Opened → Agent Analyzes → Score Calculated → Proposal Created (if score ≥ 5)
                                                     ↓
                                            PR Comment Posted
                                                     ↓
PR Merged → Agent Updates → Final Metrics → Status: Ready to Draft
```

## Scoring Criteria

The agent calculates a blog-worthiness score (1-10):

```
Score = Impact (1-3) + Complexity (1-3) + Educational Value (1-3) + Novelty (0-1)

Thresholds:
≥7: 🔴 HIGH priority (must write)
5-6: 🟡 MEDIUM priority (should consider)
3-4: 🟢 LOW priority (optional)
≤2: ⚪ SKIP (not blog-worthy)
```

### Impact (1-3)

- **3 = Major**: >$10k/year savings OR >50% improvement OR critical security
- **2 = Moderate**: $1k-$10k/year OR 10-50% improvement OR important feature
- **1 = Minor**: <$1k/year OR <10% improvement OR small enhancement

### Complexity (1-3)

- **3 = High**: Multi-package changes, architectural shifts, >1000 lines
- **2 = Medium**: Single package, moderate refactor, 100-1000 lines
- **1 = Low**: Simple changes, <100 lines

### Educational Value (1-3)

- **3 = High**: Novel solution, reusable patterns, best practices
- **2 = Medium**: Interesting approach, some lessons learned
- **1 = Low**: Routine implementation

### Novelty (0-1)

- **1 = Bonus**: Unique or creative solution
- **0 = Standard**: Standard approach

## Manual Invocation

### Using the Helper Script

```bash
# Analyze a specific PR
./scripts/propose-blog-post.sh <PR_NUMBER>

# Force analysis even for low-priority PRs
./scripts/propose-blog-post.sh <PR_NUMBER> --force
```

### Using GitHub Actions

Go to Actions → Blog Post Proposer → Run workflow

Input PR number and optional force flag.

### Using Claude Code

```bash
# In your terminal or IDE
agent:blog-post-proposer

# Then provide the PR number
Analyze PR #57
```

## Proposal Lifecycle

### 1. Initial Proposal (PR Opened)

Agent creates proposal with:
- Blog-worthiness score
- Recommended structure and hooks
- Code examples to include
- Diagrams to create
- Estimated metrics

### 2. Review and Approval

Team reviews proposal:
- Verify metrics are accurate
- Adjust scope if needed
- Approve or request changes

### 3. Drafting

Writer (human or agent) uses proposal to:
- Follow recommended structure
- Include identified code examples
- Create suggested diagrams
- Hit word count targets

### 4. Final Update (PR Merged)

Agent updates proposal with:
- Final performance metrics
- Actual results vs estimates
- Links to merged PR
- Status change to "Ready to Draft"

### 5. Publication

Once article is published:
- Update proposal status to ✅ Published
- Move proposal to archive or delete
- Link article in proposal

## Tips for Using Proposals

### For Writers

- ✅ Use proposal outline as starting structure
- ✅ Follow word count recommendations
- ✅ Include all suggested code examples
- ✅ Create proposed diagrams
- ✅ Verify all metrics before publication

### For Reviewers

- ✅ Check if score accurately reflects impact
- ✅ Validate metrics are measurable and accurate
- ✅ Ensure code examples are production code (not invented)
- ✅ Verify educational value for target audience
- ✅ Approve timeline and scope

### For Maintainers

- ✅ Archive or delete proposals after publication
- ✅ Link published articles in proposals
- ✅ Update existing articles based on merge updates
- ✅ Keep proposals directory clean (delete old/stale ones)

## Integration with CI/CD

The Blog Post Proposer is integrated into the PR workflow:

1. **GitHub Actions** (`.github/workflows/blog-post-proposer.yml`)
2. **Agent Definition** (`.agents/blog-post-proposer.md`)
3. **Proposal Template** (`docs/blog/_proposal-template.md`)
4. **Helper Script** (`scripts/propose-blog-post.sh`)

## Disabling the Agent

To skip blog post proposal for a specific PR:

Add to PR description:
```
<!-- skip-blog-proposal -->
```

Or use paths-ignore in workflow to skip certain file types.
